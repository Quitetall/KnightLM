# Two modes, two tool schemas, packet last

Proposed by the performer; the owner made the design decisions and a person accepts it.

The model plays from one fresh context packet per turn, in one of two modes with
separate tool schemas: play (competition, chat off) and coach (chat on). Each
mode sees only its own schema; the model never calls an engine; tools act on the
board only; the fixed instruction and schema come first and the packet last, so
the prefix caches. The full contract is `docs/model/modes-and-tools.md`.

Owner decisions recorded here. Coach commits by a `Provisional: <uci>` line the
model may revise; every line goes through the `submit_move` gate and the last
legal one is the move when the model stops, runs out of tokens or time, or
exhausts its retries, with the existing constrained-decoding fallback only when
none is legal. The play-mode `reasoning` field is trained from the start, so the
play completion is exactly one `submit_move` call with `reasoning` before `move`.
The retry budget is `MatchConfig::max_retries`, and read queries share the
eight-call `RuleSession` budget. A per-legal-move repetition and 50-move map is a
packet v2 experiment arm behind `PacketOptions`, off by default.

Consequences: the existing `user_text` / `user_chat` move prompt is unchanged, so
current corpora and evaluations stay valid, and the v1 packet bytes are unchanged.
The shared tool JSON lives in `crates/contract/schemas/model_tools.json`, generated by
Rust and read by Python; prompts, the play completion cases and the summarizer
cases are pinned the same way. The tools harness is opt-in in `play.rs`; existing
providers keep their path. No training row uses the new prompts or packet v2 yet.

# RustyBrickChess is the single viewer

Proposed by the performer; the owner decided it and a person accepts it.

RustyBrickChess (`apps/rusty-brick-chess`, RBC) is the one viewer for KnightLM.
The two placeholder viewers are retired: `apps/viewer`, a scaffold with no
backend, and `apps/knightlm-viewer`, an empty directory that was never tracked.
`apps/viewer` is deleted in this change; no crate, script, workflow or Makefile
target depended on it, and the workspace already excluded `apps/*`.

The Specification (`SPEC.md`, `spec/`) carries the decision: Phase 3 names RBC
as the single viewer, REQ-008 reads "The single viewer is RustyBrickChess", and
the technology pins say the same. The legacy SAS `docs/sas/KnightLM_SAS.md`
is left as it was, with its accepted revision 0.1.0 and its unaccepted proposed
0.2.1, so no SAS revision is proposed for this change. REQ-008's other claim
is unchanged: the application contains no JavaScript or TypeScript; the CDP and
MCP browser drivers under `tests/` are test tooling, not the application.

KLM-WAR-0010 delivered `apps/viewer/src/app.rs` and `board.rs` as D-001 and
D-002. Those two deliverables are removed from its `deliverables.toml`, since
the files are gone; D-003 (the RBC app shell) stays. The Warrant's prose is a
historical record of the original plan and is not rewritten.
