# Intent

Turn the raw bulk Lichess stream into the run-1 corpus: 2 million timed blitz
and rapid standard games at 1600+ (bullet excluded), reduced to decision-point packets,
joined with the lichess eval labels by normalized position key, split into
temporally-separated train and eval sets, audited for leaks, and materialized
as sharded JSONL with a provenance manifest — the load-bearing data contract
everything downstream consumes (KLM-SAS-RQ-011).

## Out of scope

- Training itself — KLM-WAR-0008.
- crawler/download mechanics: bulk files arrive hand-downloaded; the corpus
  work assumes they are on disk.

# Work Order

## Deliverables

1. Corpus ingest driver over `nota-reader`: filter to standard chess, timed
   blitz and rapid, both players 1600+, two-move mate/abandoned games
   dropped; 2M games ingested to shard JSONL.
2. Packet compiler extension: per decision point, per-arm packets + policy
   target (the played move) + a joined label when available. Tablet narrowing
   mirroring `code/crates/core`'s exp-backed format.
3. Label join: normalized position key (from FEN) >> `lichess_db_eval.jsonl`;
   depth floor 20; highest-depth row wins ties; first PV token parsed with
   the `UCI_Chess960` flavor table (KLM-WAR-0004's); cp/mate preserved; joins
   recorded as LABELS ONLY per RQ-011.
4. Splits: 200K train games; 10K eval games strictly from the newest month of
   the pool; game-family disjoint (same opening family/traditional
   neighboring transposition clusters do not straddle splits).
5. Split audit + manifest: counts, per-shard hashes, provenance keyed to file
   names and download receipts the team records; an audit that refuses to
   bless a split with a planted leak.

- **evidence:** every `GameRecord` carries bulk-source file names; the manifest ties files

- **scope:** sampled positions from the eval set checked against the lichess eval file

hashes; train/eval strictly temporal

## Residual Risk

Join cardinality: many eval rows per position with ending-variant depths; the
tie policy is decided pre-run and the audit verifies it. Disk footprint on
the order of tens of GB — sized before the run. Malformed Lichess rows are
expected and are an explicit-refusal count, not a silent skip, per RQ-004;
weekly ingest reports log refusal shapes.
