# Intent

Build `rbc-ai`, the domain and host layer behind the Assistant. It owns sessions and turns,
the tool registry, provider adapters, the agent loop, SSE events and the approval service.
The frontend and MCP consume this crate; neither reimplements it.

Out of scope: the Assistant UI, match/tournament UI, study editor, MCP transport. Those
consume this runtime.

# Basis

- Current AI is `chat_with_tools` in `apps/rusty-brick-chess/src/api.rs`: one `MODEL_URL`,
  stateless, max 3 tool rounds, no streaming, no persistence.
- Decisions: OpenAI-compatible first; keyring keys; tools with effects/policies; board writes
  revision-checked; approvals per-turn changesets and async MCP jobs; SSE; full local history.
- `rbc-context` provides `CompiledContext`; `rbc-db` v4 provides storage; `knightlm-engine`
  and the database power tools.
- Schema v4 tables from W-01.

# Work Order

Deliverables (packages PKG-020..PKG-028):

1. `rbc-ai` crate with `protocol`/`core`/`host` features; session/turn DTOs; SQLite store;
   create/list/rename/archive/delete; append-only turns.
2. Tool registry: names, JSON schemas, versions, effects (`read`, `board-write`,
   `session-write`, `destructive`, `external`), mode/origin policy.
3. Read tools: position, history, legal moves, analyze, eval, openings, database, tablebase,
   study read. Board tools: play, arrows, circles, annotate, notes, create/copy, revisions,
   lock/publish checks.
4. Provider trait + OpenAI-compatible adapter: chat completions, tools, streaming SSE, usage,
   normalized errors, timeout/cancellation, retries.
5. Agent loop: compile context, call provider, execute tools, feed results, retry illegal
   moves/tool errors, max rounds, cancellation, store turn/context hash.
6. SSE event stream + replay from `after`; replay endpoint rebuilds context and returns
   match/diff.
7. Approval service: per-turn changesets, pending/approved/denied/expired, auto-approve
   scopes, audit; async approval ids for MCP.
8. Mock provider + integration tests for streaming, tool loops, retries, conflicts, approvals.

Seams:

- `rbc-context` compiles; `rbc-ai` supplies evidence and stores the result.
- The server routes (W-04/W-09) are thin adapters over `rbc-ai`.
- MCP and the in-app AI share the same tool registry and policy engine.

Autonomy and escalation:

Tier T2. Escalate changes to the tool effect model, approval semantics, or provider contract.
The performer owns internal module layout and error codes.

Rollback:

Additive crate + v4 tables. If the runtime is reverted, sessions/turns remain readable but
inert; no chess data is touched.

# Assurance



## Gate Adequacy

Required at `basic`. **Adversarial question:** how could this look done and not be?
Each obligation pairs a positive claim with a refusal: a stale revision, a locked board, a
missing hash, an unapproved write, or a dropped required section. The package test in
`openwarrant/packages.json` is the executable gate; the obligation text is the contract.


## Obligations

### OBL-001: a provider stream is parsed into events without dropping a delta

- **scope:** the OpenAI-compatible adapter against recorded chunks, including tool
  call accumulation and reasoning deltas.
- **evidence:** `crates/ai/tests/provider.rs` and `crates/ai/tests/stream.rs`.

### OBL-002: a tool that fails does not take the turn with it, and a retry is bounded

- **scope:** the agent loop's handling of tool errors and provider retries.
- **evidence:** `crates/ai/tests/agent_loop.rs`.

### OBL-003: a write the policy requires approval for is queued, not performed

- **scope:** the policy gate on board writes. It makes no claim about what happens
  after a person approves — that is `KLM-WAR-0014`'s approval path and is covered by
  the approvals obligation below.
- **evidence:** `crates/ai/tests/write_tools.rs`, and `frontend/tests/cdp/cdp_ai_approvals.js`
  (`AI_APPROVALS_PASS`) which shows one pending `play_move` row with the board untouched.

### OBL-004: an approval is answered once, expires, and cannot be replayed

- **scope:** resolution of a queued approval: not found, already resolved, expired.
- **evidence:** `crates/ai/tests/approvals.rs`.

### OBL-005: approving performs exactly the write that was reviewed

- **scope:** the replay of the stored call on approval. A refused write
  (conflict, copy required) leaving the approval approved is part of the claim.
- **evidence:** `frontend/tests/cdp/cdp_ai_approvals.js`: the board reaches revision 2
  with `{"moves":["e4"]}` after approving, and the row reads `moves 0 -> 1 (e4)` first.

### OBL-006: an unconfigured subsystem answers unavailable rather than guessing

- **scope:** read tools with no engine, no openings set, no database, no tablebase.
- **evidence:** `crates/ai/tests/read_tools.rs` asserting `result_code::UNAVAILABLE`.
